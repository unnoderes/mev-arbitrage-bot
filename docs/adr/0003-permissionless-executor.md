# 套利合约取消 onlyOwner，改为利润自校验的无许可执行

状态: accepted（取代 `docs/03-smart-contract.md` 中的 `onlyOwner` 设计）

原合约用 `onlyOwner` 限制 `executeArbitrage()`，这意味着私钥泄露即可清空合约，也意味着机器人无法开源。但套利合约本身能在链上验证自己是否赚钱，所以访问控制是多余的：任何人调用都无害。

## 决策

去掉 `onlyOwner`。安全性完全由一条不变量保证：**归还闪电贷之后，计价代币余额的增量必须 ≥ `max(调用者给的 minProfit, ownerMinProfit)`，否则整笔回滚**。利润留在合约里，由 owner 通过 `withdraw` 提取；调用者自付 Gas。

## 代价与必要的配套

- 必须有 `ownerMinProfit` 下限，否则任何人可以用 `minProfit = 0` 让合约执行一条实际亏损的路由。
- 必须有 router 与代币双白名单，否则「任何人可调用」会退化成「任何人可任意调用」。
- 每一步的 `minOut` 必须由调用者提供并由合约逐跳校验，否则中间步骤可以被夹击而不影响最终余额检查。
- 余额检查必须在闪电贷归还**之后**，否则借来的本金会虚增起始余额。
